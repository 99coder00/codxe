# CoD Xe T4: Call of Duty: World at War

## Singleplayer

### CoD Xe data location

Package the T4 singleplayer data under _codxe\t4:

~~~text
_codxe\
  t4\
    codxe.json
    mods\<active_mod>\...
    zone\...
    usermaps\...
~~~

The same archive can be extracted into the game directory, a USB device root,
or the internal HDD root. The lookup order is game:\_codxe\t4,
game:\_codxe (the existing layout), Usb0:\_codxe\t4 through
Usb4:\_codxe\t4, then Hdd1:\_codxe\t4. The first existing directory
becomes the only active root for this launch. Config, mods, fastfiles,
usermaps, and loose sounds are read from that root; missing files do not
fall back to another device. Usermap fastfiles take precedence over zone
fastfiles within the selected root. USB and HDD never search an un-nested
_codxe folder; that layout applies only to the game directory.

### Usermaps list

The Nazi Zombies map list (the `levels_unlock` menu) can show every map of the
`usermaps` folder instead of a fixed set: CoD Xe lists the folders holding a
`<map>\<map>.ff` each time the menu opens, sorted by name, and fills the rows of
the menu with them. The menu must be made for it: `python -m t4ff menu
<game>\_codxe\t4` (see [tools/t4ff](/tools/t4ff/README.md#map-list-in-the-menu))
rewrites CoD Xenon's `zone\patch_ui.ff` with 13 rows that scroll with the D-pad,
LB / RB for a page, and a preview of the focused map.

Each map folder can describe the map:

~~~text
usermaps\<map>\
  <map>.ff
  description.txt   first line: the map's name in the list, next lines: its description
  preview.txt       a material of the menu zone to show as its picture (CoD Xenon's maps)
~~~

Without `description.txt` the folder name is shown (`nazi_zombie_wh` as "Nazi
Zombie Wh"). `t4ff` writes it for the maps it converts, and `t4ff menu` for CoD
Xenon's maps, from their menu.

The menu and CoD Xe talk through dvars: CoD Xe sets `ui_codxe_map<row>` and
`ui_codxe_mapcmd<row>` (the name and `devmap <map>` of each row, empty when the
row is unused), `ui_codxe_mapoffset`, `ui_codxe_mapmore`, `ui_codxe_maprange`
and the preview `ui_codxe_maptitle`, `ui_codxe_mapdesc`, `ui_codxe_mapimage`;
the menu sets `ui_codxe_focus` (the focused row) and `ui_codxe_scroll` (rows to
scroll).

## Multiplayer

### Dvars

#### `noclip_brushes` _(string)_

A server-info dvar that controls which brushes have player collision disabled. It holds a space-separated list of brush indices.

Special values:

- `""` - Restores all brushes to their original collision state.
- `"*"` - Disables player collision on every brush in the clipmap.

```text
set noclip_brushes "";    // reset all brush collision
set noclip_brushes "*";   // disable all brush collision
set noclip_brushes "4 7"; // disable collision on brushes 4 and 7
```

### GSC Functions

#### `GetPlayerclipBrushesContainingPoint(vec3 <point>)`

Returns an array of playerclip brush indices whose bounds contain the given point.

Usage example:

```gsc
brushes = GetPlayerclipBrushesContainingPoint(self.origin);
```

## Converting PC Usermaps

[`tools/t4ff`](/tools/t4ff/README.md) converts PC custom zombie maps (usermaps) into fastfiles for `_codxe/t4/usermaps`: models, animations, the world, effects, weapons, materials and scripts are converted to the console formats, textures are tiled and compressed, sounds are encoded to XMA, and technique sets (console shaders) are copied from Xbox 360 fastfiles you provide. It reports the memory the converted map needs so it can be kept within the console's limits.
